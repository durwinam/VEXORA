# VEXORA 2.0.0

VEXORA is a lightweight configuration shop with FastAPI, HTML/CSS/JavaScript, SQLite, provider adapters, receipt workflow, Telegram notifications and protected backups.

## Why this layout

The app follows the deployment pattern used by mature panels:

- application binds privately on `127.0.0.1:6000`
- public access is handled by Nginx
- the public URL is controlled by host + path
- TLS certificate paths are explicit configuration
- `.env` is generated by the installer and never required as a source file

## Installation

```bash
curl -fsSL https://raw.githubusercontent.com/durwinam/VEXORA/main/install.sh -o /tmp/vexora-install.sh && sudo bash /tmp/vexora-install.sh
```

The installer asks:

**1. Domain + HTTPS (Recommended)**

Example:
`https://panel.example.com/vexora/`

**2. IP + HTTPS**

Current Let's Encrypt supports public IP certificates through Certbot's IP-address support. These certificates are short-lived, so VEXORA installs an automatic renewal timer.

Example:
`https://203.0.113.10/vexora/`

**3. HTTP :8080**

Fallback:
`http://203.0.113.10:8080/vexora/`

The VEXORA process itself remains on `127.0.0.1:6000`; port 6000 is not intended as the public URL.

If port 443 is already occupied, the installer does not stop the existing service. VEXORA stays available on the 8080 fallback.

## Environment

The important deployment variables are:

```text
VEXORA_HOST=127.0.0.1
VEXORA_PORT=6000
VEXORA_BASE_PATH=/vexora/
VEXORA_SHOP_PATH=/vexora/shop/
VEXORA_ADMIN_PATH=/vexora/admin/
VEXORA_PUBLIC_HOST=panel.example.com
VEXORA_PUBLIC_PORT=443
VEXORA_SSL_CERTFILE=
VEXORA_SSL_KEYFILE=
```

This separation means the application can be moved behind another reverse proxy without changing its business logic.

## Certificate renewal

Domain certificates are obtained using ACME/Let's Encrypt webroot validation.

IP certificates use Certbot's IP-address support with the `shortlived` profile. A systemd timer checks renewal every six hours and reloads Nginx after successful renewal.

If ACME issuance fails, VEXORA does not fake HTTPS status; the installer reports the failure and leaves the HTTP 8080 fallback available.
